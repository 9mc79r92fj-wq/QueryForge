# QueryForge 面试讲解指南

## 一句话介绍

QueryForge 是一个单机部署的企业知识库 RAG 后端：文档异步入库、四种检索策略（BM25 / Dense / Hybrid / Adaptive）、版本一致的索引快照、带引用校验的流式问答，以及可观测的运行指标。

## 可以主动讲的工程点

1. **版本一致性**：IndexSnapshot 用单事务固定 revision 与可见版本；文档更新后旧版本立即退出新快照。
2. **幂等入库**：分块 ID 由版本 + 序号确定性生成；版本激活在单事务完成；文件锁 + 持久化尝试次数防重复。
3. **缓存正确性**：缓存键含 revision 与可见版本；降级路径不写缓存。
4. **引用校验**：只接受本轮检索结果中的编号，非法即拒答——但要说明这只能保证"引用格式合法"，不等同事实正确。
5. **V2 路由**：查询前特征 → 策略表 → 加权 RRF；精排按预算与分数差选择性触发（本轮已实现并测试）。

## 要诚实说明的部分

- 融合策略在 500 篇子集上没有超过 Dense，这是真实结果，不要包装成"自适应最优"
- Reranker CPU 延迟 17 秒级，因此公网默认关闭
- V2 的 Agentic RAG、扩大 Benchmark、TracePilot 互通尚未完成
- 免费平台实例会休眠，首次访问需要唤醒

## 可能被追问的问题

- 为什么 RRF 不用原始分数？→ 量纲不同，排名融合更稳
- 怎么保证任务不重复执行？→ 幂等键 + 文件锁 + 状态机 CAS
- 断线后 SSE 怎么处理？→ 草稿 delta + final 覆盖，取消时清空草稿
- 预算怎么防刷？→ SQLite 原子扣减 + 会话隔离 + 限流
